# RF4 Assistant Pro v2.3.25 — модуль кафе

## Выполнено

Логика кафе вынесена из основного `StatisticsViewModel` в
`StatisticsViewModel.Cafe.cs`:

- снимки и café bindings;
- добавление, обновление и удаление снимков;
- загрузка истории кафе;
- перепроверка сохранённых отметок;
- пересборка совпадений уловов с предложениями;
- сохранение и восстановление ID предложений;
- удаление связанных изображений.

Публичные свойства, XAML bindings, формат JSON и общий механизм атомарного
сохранения сохранены.

Копирование `CafeOffer` перенесено в `RF4Assistant.Core/Cafe/CafeOfferCloner.cs`.
Это одновременно устраняет потерю `RawFishName`, `FishCatalogId` и
`RecognitionSource` при обновлении предложений кафе.

Для временного ручного QA добавлено окно `Windows QA` в центре диагностики.
Оно позволяет отмечать каждый сценарий как «Успешно», «Сбой» или
«Ожидает», сохраняет состояние в JSON и пишет события в
`Logs/WindowsQa.log`. `ReleaseReady` становится `true` только после
успешного прохождения всех десяти проверок.

## Проверка

Добавлены регрессионные сценарии сохранения OCR-метаданных и статусов
Windows QA. В тестовом runner зарегистрировано 102 сценария.

Restore, Release build, 102 теста и self-contained `win-x64` publish
успешно выполнены кросс-сборкой с .NET 10 SDK. Запуск WPF, keyboard hook,
захват экрана и OCR всё ещё требуют ручной проверки на Windows.
Скрипт `qa/Run-WindowsQa.ps1` сообщает
`PreflightStatus=PASS`, `ManualQaStatus=PENDING` и
`ReleaseReady=false`, пока ручная проверка не завершена.
