# Windows QA для RF4 Assistant Pro v2.3.31

Этот документ закрывает ручную часть этапа 18. Автоматическую часть нужно
запускать на Windows 10/11 x64 с установленным .NET 10 SDK:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\qa\Run-WindowsQa.ps1 -LaunchInteractive
```

Скрипт выполняет `restore`, Release-сборку, интеграционные тесты и
self-contained `win-x64` publish. Результаты и логи сохраняются в
`artifacts\windows-qa`.

Дополнительно в приложении откройте **Центр диагностики → Windows QA**.
Для каждой проверки выберите `Успешно`, `Сбой` или `Ожидает` и при
необходимости добавьте комментарий. Результаты сохраняются в
`%LOCALAPPDATA%\RF4AssistantPro\windows-qa-checklist.json`, а события —
в `Logs\WindowsQa.log`. Поле `ReleaseReady` становится `true` только
после успешного прохождения всех десяти проверок.

## Матрица ручной проверки

Заполняйте столбец «Результат» значениями `PASS`, `FAIL` или `N/A`. Для
ошибок укажите путь к логу и приложите диагностический ZIP.

Smoke-прогон v2.3.28 от 2026-10-04 подтвердил запуск, привязку RF4,
10 карточек кафе, водоём, наживку и захват пяти рыб садка. Он также выявил
регрессию очистки садка после применения изображений. В v2.3.29 сценарий
садка должен быть повторён полностью; backup/restore, экспорт, DPI и кафе

## Критерии завершения этапа 18

Этап можно отметить выполненным только если:

1. `Run-WindowsQa.ps1` завершился со статусом `PRECHECK_PASS`.
2. Все применимые строки матрицы имеют `PASS`.
3. Нет необработанных исключений в `Logs\Errors.log`.
4. Создан и просмотрен хотя бы один backup round-trip с реальными PNG.
5. Зафиксированы версии Windows, .NET SDK, режим сборки и дата проверки.
